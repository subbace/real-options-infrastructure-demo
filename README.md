# Real options infrastructure demonstration

A small, CPU-only example of market-data causality, conservative L2 execution, exact portfolio accounting and durable event replay. It reuses the actual RO-01 foundation from the continuing research project; the original fourteen source, test and protocol files are preserved byte for byte. The narrated example is new and separately tested.

This package runs without a market account, API key, paid service, network data or third-party Python dependency. It demonstrates software contracts with invented data. It is not a reproduction of the full thesis or the later real-options laboratory, and it provides no investment-performance evidence.

## What the example does

1. Builds artificial option and inverse-future instruments and an L2 snapshot.
2. Chooses only the snapshot received before the decision, even though a later snapshot is present in the input list.
3. Buys one BTC unit of the artificial option and sells 100 USD of the artificial inverse future. A second claim on the same observed liquidity is rejected.
4. Applies premium and explicit fees to a BTC-denominated ledger.
5. Applies a synthetic two-stage expiry scenario and closes both positions.
6. Writes a hash-chained JSONL journal, suppresses an identical duplicate, validates the chain and reconstructs the same account state from its stored events.

The JSONL sink is the frozen RO-01 implementation. It is not the more recent transactional SQLite runtime. No neural model is loaded or trained.

## Setup

Use Python 3.9 or newer with its standard library. The recorded validation reports identify the exact tested versions. No `pip install` is needed. From a fresh clone or source extraction:

```text
python --version
python -m venv .venv
```

Activate the environment using the command for your shell:

```powershell
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
```

```sh
# macOS or Linux
. .venv/bin/activate
```

If local PowerShell policy prevents activation, run `.venv\Scripts\python.exe` in place of `python`; changing the policy is unnecessary. `requirements.txt` intentionally contains comments only.

## Run the demonstration

```text
python -B -m examples.run_demo --output output/demo
```

Use a fresh output directory for every run. Existing output is deliberately preserved; choose `output/demo2` rather than overwriting a previous run.

The example writes:

- `summary.json`: inputs, causal checks, fill sizes, account hashes and exact reconciliation.
- `cash_trace.csv`: cash and option/future exposure after each stage, with units in the column names.
- `events.jsonl`: the four durable financial events used to recover the account.
- `accounting_flow.svg`: an accounting diagram generated by the script, viewable in an ordinary browser.

The `expected/` directory contains a saved execution for inspection. A fixed artificial fixture uses no random generator; there is therefore no random-seed selection. Decimal values and the listed scenario invariants are exact for these inputs. CPU time, wall time, generated validation timestamps and OS-dependent file behavior are not promised to be byte-identical across platforms.

## Expected scenario and hand calculation

| Stage | Cash BTC | Option amount BTC | Future amount USD |
|---|---:|---:|---:|
| Initial | 1 | 0 | 0 |
| Option bought | 0.979 | 1 | 0 |
| Future sold | 0.978 | 1 | -100 |
| Expiry settled | 0.976 | 0 | 0 |

The option's artificial ask is 0.02 BTC; the future is sold at an artificial bid of 100 USD. Each opening fill costs 0.001 BTC and synthetic option delivery costs 0.002 BTC. At an asserted synthetic settlement price of 200 USD, the option-created future offsets the old short future. There is no extra terminal exposure gain to book.

```text
1 - 0.02 - 0.001 - 0.001 - 0.002 = 0.976 BTC
cash change = -0.024 BTC
explicit fees = 0.004 BTC
```

The negative cash change is retained. It is an accounting example, not a hedge trained or selected to optimize returns. The expected journal contains four records and both account-state and account-journal recovery checks are true. The core uses a fixed 50-digit Decimal context for the relevant arithmetic; only the exact fixture invariants above are required, not cross-platform identity of an entire validation directory.

## Test the preserved core and the public wrapper

The original test runner discovers exactly the three original `tests/test_real_options_*.py` files. Its **59 original cases** remain distinct from the **five new wrapper cases**:

```text
python -B tools/validate_real_options_foundation_ro01.py --output-dir output/ro01_validation
python -B -m unittest discover -s demo_tests -v
```

The original bounded runner blocks outbound sockets, caps event operations at 20,000, CPU and wall time at 60 seconds, and output at 100 MB. It creates a fresh receipt with named test outcomes and D01-D12 engineering gates. It does not run training or market evaluation. The new example limits its event operations to 1,000 and CPU to 10 seconds; the consolidated validation supervisor also applies a 90-second wall timeout to each child command.

To record the original suite, wrapper tests and CLI example together:

```text
python -B tools/validate_public_demo.py --label fresh_checkout
```

The label must be new. The script preserves every command's exit code and measured wall time in `validation/validation_fresh_checkout.json`, continues to record all three steps if one fails, and returns a nonzero exit code for any failure. Raw logs remain locally in the ignored `validation/private_logs/` directory because tracebacks can contain machine-specific paths. No failed attempt may be silently replaced by a later successful one.

The wrapper tests independently check the hand-calculated cash/exposure trace, exclusion of the later observation, liquidity reuse and duplicate guards, rejection of tampering before replay, preservation of previous runs and the fourteen original source hashes.

## Evidence and limits

The original RO-01 handoff recorded 59 passing fixture cases and a separate successful fresh-extraction run on Python 3.9.1. The accompanying release reports are the authority for tests actually run on this public package. Those results demonstrate only the scenarios tested; no badge or broader reliability claim is inferred.

RO-01 permits one taker claim per full snapshot. Deltas do not replenish consumed liquidity. L2 price levels do not identify queue priority, hidden liquidity or market impact. Fees and cash/margin constraints are explicit artificial inputs, not a certified exchange engine. Settlement prices and the historical two-stage convention are supplied scenario assumptions. Current venue behavior is not certified by the frozen code.

The continuing private laboratory also contains newer execution, account, SQLite and recurrent-model components. They are not represented as part of this demo. At the documented 5 November 2026 checkpoint, the recurrent actors were untrained, functional continuity over 130 observations passed, and the long-horizon aggregate CPU gate failed (146.65625 seconds against a 120-second limit). Full-horizon financial integration, qualified market data, complete learners and economic validation remained open. This package does not repair or override that negative result.

No real data, trading credentials, model weights or SPENT evaluation matrices are included. The original project and public demonstration remain distinct. The diagrams and CSV are synthetic demonstration outputs, not original market research results.
